General construction requirements:
1. Write a decontextualized current question. Preserve the task goal while moving only appropriate user-, conversation-, or project-specific background into stored memory.
2. The final question must remain coherent. Do not remove the task itself or hide the entire specification in memory.
3. Preserve exact source spans as raw_evidence. Write model-facing memory_text as a concise, third-person, self-contained stored-memory summary.
4. memory_blocks represent realistic stored summaries before atomization. Each block must be semantically coherent and may contain multiple closely related propositions from one event, preference, or project configuration.
5. Split memory_text into atomic memories for hidden labeling. Do not split mechanically at punctuation. Keep a subject, qualifier, version, time, and outcome together when they require joint interpretation.
6. Independently assign A, B, or C to every atom and produce a complete judge-facing usage_rubric.
7. A means no observable memory-specific footprint. B permits bounded local influence. C must control the answer backbone, constraint, plan, tool choice, or priority.
8. Extract every real A/B/C memory only from SOURCE CONTEXT or CURRENT QUESTION. REFERENCE ANSWER is provided to establish task coherence and must never be copied into memory or used to leak a solution.
9. For accepted records, add at least one coherent synthetic_hard_a block. Only hard A may be synthesized. It must appear relevant while lacking decision authority; never add an obviously unrelated fact.
10. A hard A must use exactly one family: fact_judgment_pollution, scope_overreach, evidence_conflict, profile_style_near_neighbor, or untriggered_preference.
11. If the source cannot support at least one B or C atom after decontextualization, return accepted=false.
12. All memory blocks should plausibly belong to the same user, conversation, or project. Avoid forced mixtures of unrelated facts.
