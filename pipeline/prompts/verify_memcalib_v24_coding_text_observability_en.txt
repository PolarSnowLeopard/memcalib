The intended label semantics are:
- A + ignore: the ideal answer must be observably identical with and without the
  atom. Any legitimate mention, caveat, plan change, correction, or detail caused
  by the atom means it is not A. A proposition may still appear in the answer
  when it is independently required by the current question or ordinary task
  knowledge; that is not use of the A atom. Judge counterfactual influence, not
  raw string occurrence.
- B + apply/correct: the atom has bounded supporting influence.
- C + apply/correct: the atom controls a core decision, constraint, dependency,
  ordering, output, or failure behavior.
- Explicit correction is observable use and cannot be A.

Audit the record-level properties:
1. task_family_fidelity: the question genuinely matches its assigned family.
2. natural_language_only: the question clearly requests prose rather than source
   code, a patch, executable pseudocode, or code blocks.
3. semantic_equivalence: compare original_question/original_reference_answer
   against question/reference_answer. The revision must preserve the original
   practical software-engineering goal while changing the requested response
   form from executable code to natural-language reasoning. The revised
   reference answer is memory-conditioned: it may and should add behavior
   warranted by valid B/C atoms even when that behavior is absent from the
   original question or original reference answer. Do not call such a
   memory-warranted addition a semantic change. Compare the two versions for
   preservation of the unscored practical task, inputs, outputs, and mechanism;
   audit B/C additions separately under the atom checks.
4. reference_completeness: the prose reference answer explicitly contains every
   B/C minimal_evidence item, gives a complete practical answer to the revised
   question, and does not rely on variable aliases, helper functions, or
   unstated execution semantics.
5. runtime_independence: a judge can score the response from answer text alone
   without running code, tests, tools, or hidden state.

Audit every atom in supplied order:
- label_action_validity: whether A/B/C and ignore/apply/correct are valid for the
  revised question under the counterfactual definition.
- answer_text_observability: whether correct use, under-use, and over-use can be
  distinguished directly from natural-language answer text.
- rubric_objectivity: whether the contract and rubric define concrete evidence
  rather than hidden intent or runtime-only behavior.
- query_value_status: whether the question text itself supplies the atom-specific
  value or constraint. Use not_supplied, partially_supplied, or fully_supplied.

For every B/C atom, also apply these requirements when deciding the verdicts:
- Same-atom entailment: every minimal-evidence item and required answer behavior
  must be directly supported by that atom's own text or evidence. Do not allow a
  rubric to import a technology, provider, path, recommendation, application
  domain, or conclusion from another atom or merely from the reference answer.
- Cross-atom attribution: compare the rubric against all atoms. If another atom
  is the better semantic source, fail rubric_objectivity for the misattributed
  rubric and any resulting duplicate or missing attribution.
- Magnitude preservation: B must remain bounded supporting influence. Fail
  label_action_validity if the rewritten task makes a B value control the core
  answer. C must control a core decision or behavior; fail if it has become only
  supporting.
- The benchmark intentionally evaluates whether an assistant uses relevant
  retrieved memories. A valid B/C atom is therefore allowed to supply a user
  preference, project context, technology, path, or constraint that the question
  deliberately leaves unstated. Absence from the question is not irrelevance,
  circularity, semantic drift, or query leakage. Fail relevance only when the
  atom cannot legitimately influence the original practical task even as
  additional user/project context.
- The original reference answer is a legitimate source for unscored practical
  solution details such as the general mechanism, algorithm, diagnosis, or
  standard tool behavior. Those details need not be supplied by a memory atom.
- Neither the original nor revised reference answer is an evidence source for a
  scored atom. A B/C required element must still be entailed by that same atom.
- Do not fail reference_completeness merely because the revised answer contains
  useful unscored details from the original reference answer. Fail only when

  or are incorrectly attributed to a B/C rubric.

Judge label_action_validity independently from query_value_status. If a C atom would
