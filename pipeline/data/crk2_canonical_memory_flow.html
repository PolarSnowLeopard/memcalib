CRK-2 Canonical Memory Benchmark 构建流程

这一版把 raw evidence 和 stored memory 显式分离：原始证据只用于审计和复现，真正进入被测模型上下文的是第三人称、总结式、可独立理解的 canonical memory。

Source Audit evidence Stored memory ABC + rubric Quality gate
01 Source seed

公开问答样本

读取 normalized public QA，保留 source id、topic、raw_question、doctor_answer。

  • 当前仍是 medical-heavy seed
  • 后续可接入通用对话来源
02 Decontextualize

去背景化当前问题

生成 question，只保留当前任务，移除会进入 memory 的个人事实、历史、约束和偏好。

03 Evidence extraction

抽取 raw evidence

从 raw_question / doctor_answer 中抽取可审计证据片段；它可以是第一人称或原文噪声。

  • 用于复现和人工核查
  • 不直接提供给被测模型
04 Canonicalize

生成 stored memory block

把 raw evidence 改写成第三人称、总结式、可独立理解的 memory_text。

  • 模拟真实记忆系统的存储条目
  • 不能直接复制一人称原句
05 Atomize

拆分原子记忆

只在子信息能独立判断、独立使用、独立过用/漏用时拆分；同一事件链可保留为一个 atom。

  • atomic text = canonical memory
  • atomic evidence = 对应证据片段
06 Supplement hard A

只补 hard A

补充看似相关但当前无决策权的干扰记忆；不补 easy A，不合成 B/C。

  • fact_judgment_pollution
  • scope_overreach / evidence_conflict
  • profile_style_near_neighbor / untriggered_preference
07 ABC relabel

全量 A/B/C 标注

对每个 atomic stored memory 独立标注使用强度：A no footprint，B bounded footprint，C answer-controlling。

08 Judge rubric

生成 judge-facing rubric

每个 atom 都带 construction_target、usage_rubric、observable_checks，并提供 RL judge 可用的客观判据。

09 Schema gate

结构质量门

检查必填字段、block-atom 链接、A/B/C 与 rubric weight 对齐、synthetic hard A 是否存在。

10 Memory-form gate

记忆形态质量门

拒绝明显一人称 stored memory；确保 raw evidence 与 canonical memory 职责分离。

11 Distribution audit

分布与难度审计

统计 topic、A/B/C、hard A family、source、atom 数量和 parent block 数量，标记需要人工复核的样本。

12 Benchmark artifact

产出 benchmark

输出 JSONL、summary 和单样本 HTML viewer；评测时模型看到 question + canonical memory，judge 使用 rubric。

模型输入面

被测模型只能看到 canonical stored memory，不把 raw evidence 当作上下文。

审计输入面

raw evidence 保留原文，用于追溯每条 stored memory 是否来自公开问答或 synthetic hard A。

评估输入面

judge 使用 atom-level construction_target 和 usage_rubric 判断正确使用、under-use 和 over-use。
