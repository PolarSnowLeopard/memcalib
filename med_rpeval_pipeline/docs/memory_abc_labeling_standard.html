Method draft for a memory-use benchmark

从整段记忆相关性，转向原子记忆的选择性使用。

本草案面向论文中的 benchmark 构建方法。核心观点是：真实对话记忆通常不是原子的，一段记忆可能同时包含偏好、事实、约束、经历和无关信息。 因此，benchmark 不应只评测模型是否使用了某条 memory block，而应评测模型能否在其中识别并使用正确的 atomic memories， 同时抑制无关、重合、过时或冲突的信息。

1. 标注单位

我们将记忆表示为三层结构。ABC 标签不直接作用于整段自然语言记忆，而是作用于 atomic memory 与当前 query 之间的关系。

Memory block

自然语言形式的一条记忆，可以是一句话、一段摘要或若干历史信息的合并。它是模型实际看到的粗粒度输入。

Atomic memory

从 memory block 中析出的最小可判定用户相关命题。每个 atomic memory 只表达一个事实、偏好、约束、目标、经历或能力信息。

Atom-query relation

某个 atomic memory 相对当前 query 的规范性使用关系，即 A/B/C 标签。该关系取决于 query，不是 atomic memory 的固有属性。

方法学约束：若一条 memory block 包含多个 atomic memories，则它本身不应被强行赋予单一 ABC 标签。整段记忆的标签只能作为聚合视图，例如“contains A/B/C atoms”。

2. ABC 关系定义

ABC 描述的是 atomic memory 对当前 query 的 necessity of use，不是记忆的重要性、用户偏好强度，也不是模型是否应该“显得个性化”。

A Non-applicable

该原子记忆不应影响当前回答。使用它会导致无关个性化、跑题、错误推断、隐私暴露、刻板化或过度结合。

should be ignored

B Auxiliary

该原子记忆可以改善回答质量，例如语气、例子、推荐排序、解释深度或交互方式，但不是完成任务的必要条件。

may improve response

C Necessary

该原子记忆是生成正确回答的必要条件。忽略它会导致答案错误、违反约束、不可执行或不符合稳定需求。

must affect response
Let q be the current query, m_i an atomic memory, and y* the ideal response. The label L(q, m_i) is defined by the normative effect of m_i on y*: A: m_i should not affect y* B: m_i may improve y* but is not required for correctness C: m_i is required for correctness, feasibility, safety, or constraint satisfaction

3. 反事实准则

为了降低主观性，标注者不直接问“这条记忆相关吗”，而是执行反事实判断。

C test
移除该 atomic memory，理想答案是否不再正确或不可执行？ 如果答案的核心内容、约束满足、安全性、可行性或目标达成发生变化，标为 C。
B test
移除该 atomic memory，答案仍正确，但是否明显更不贴合用户？ 如果只影响表达方式、例子选择、解释粒度、推荐排序或交互效率，标为 B。
A test
使用该 atomic memory 是否无帮助或有害？ 如果它与任务无关，或会引入不必要的个性化、隐私、偏见、过时信息或指令冲突，标为 A。

形式化判定测试

测试 A B C
Removal test 理想答案不变，或应主动避免引用该信息。 理想答案仍正确，但个性化程度或实用性下降。 理想答案错误、不完整、不可行或违反约束。
Opposite test 替换成相反原子信息，答案不应改变。 替换后表达、例子或排序可以改变。 替换后核心答案必须改变。
Instruction conflict 当前 query 明确排除该记忆时，旧记忆让位。 若不冲突，可作为辅助上下文。 仅当该原子记忆构成当前任务硬约束时保留必要性。

优先级：先判定 C，再判定 B，最后判定 A。若一个原子信息既可能辅助又可能有害，应根据当前 query 的规范性要求判断；如果无法稳定裁决，该样本不进入主评测集。

4. 非原子记忆样例

下面的例子展示为什么必须先拆分 atomic memories。整段记忆无法被单一 ABC 标签准确描述。

memory block
我不吃花生，喜欢日式料理，去年去过东京，平时预算比较紧。
query
帮我安排一份东京三天餐饮计划。
atom 1
C 我不吃花生。餐饮计划必须避开花生及相关风险。
atom 2
B 我喜欢日式料理。可影响推荐排序，但不是完成计划的必要条件。
atom 3
A 我去年去过东京。若 query 没要求避开已去地点，直接使用会引入无关假设。
atom 4
B 我平时预算比较紧。可倾向推荐经济选项；若 query 明确要求严格预算，则可转为 C。

论文叙事：该例说明我们评测的不是“模型是否使用这段记忆”，而是模型是否能在同一 memory block 中使用 C、适度使用 B、抑制 A。

5. 重合与冲突

多条记忆之间可能在 atomic memory 层面重合。重合不应只被视为数据清洗问题，而应成为 benchmark 的一个诊断维度。

关系类型 定义 评测意义
Non-overlap 不同 memory blocks 的 atomic memories 在语义上互不重合。 适合作为主评测集，保证标签和归因清晰。
Redundant overlap 多条记忆表达同一 atomic memory，例如“我对花生过敏”和“我不能吃花生”。 测试模型能否合并冗余信息，而不是重复引用或过度加权。
Partial overlap 两条记忆部分共享 atomic memory，但各自包含新增信息。 测试细粒度抽取能力：模型是否只使用相关原子信息。
Conflict overlap 多条记忆针对同一 canonical claim 给出不同取值或不同时间版本。 测试模型处理更新、时效、冲突和当前指令优先级的能力。
Compositional dependency 答案需要组合多条 atomic memories 才能确定。 应作为高级子集，避免与主集的单 atom 归因混淆。
memory 1
我对花生严重过敏。
memory 2
花生酱会让我过敏，所以我一般不碰。
atom view
两者共享 canonical claim: user_has_peanut_allergy。主评测集中应避免同时出现；诊断子集中可保留，用于测试冗余记忆处理。

6. 数据子集设计

为了同时保证主评测的可解释性和 benchmark 的诊断能力，建议将数据组织为主集和若干诊断子集。

Main set: clean atom-level evaluation

  • 每个 atomic memory 可独立判定 A/B/C。
  • 同一样本内避免 canonical claim 重合。
  • query 不直接泄露被评测 atomic memory。
  • 优先保证标签可分、可复现、可人工一致标注。

Diagnostic sets: realistic memory complexity

  • mixed-label memory blocks：同段记忆含 A/B/C atoms。
  • redundant overlap：多条记忆表达同一原子信息。
  • partial overlap：多条记忆部分重合且各有新增信息。
  • conflict and stale memory：记忆之间或记忆与当前指令冲突。

7. 质量验证

质量验证应服务于论文可信度：证明标签不是主观猜测，数据不是仅由模型自洽生成。

验证维度 核心问题 论文中可报告的证据
Atomicity 每个 atomic memory 是否只包含一个可独立判断的命题？ 原子拆分指南、人工抽检一致率、典型错误类型。
Label separability A/B/C 是否能通过反事实准则稳定区分？ 人工双标一致性、分歧样本分析、被排除边界案例比例。
Counterfactual consistency 移除或反转 atomic memory 后，理想回答变化是否符合标签？ removal/opposite test 的通过率与人工复核结果。
Leakage control query 是否直接暴露了需要被记忆提供的信息？ 泄漏检测规则、泄漏样本剔除比例。
Overlap control 主集中 canonical claims 是否保持非重合？诊断集中重合类型是否清晰？ overlap taxonomy、各子集规模与示例。
Human audit 人类标注者是否能按指南复现标签？ raw agreement、Cohen's kappa 或 Krippendorff's alpha。

8. 评估报告

Benchmark 的贡献应体现在系统覆盖 selective memory use 的不同失败模式，而不是只覆盖领域多样性。

维度 建议取值 用途
Label A / B / C 分别报告 necessary memory recall、auxiliary memory use、non-applicable memory suppression。
Memory type preference, constraint, profile, goal, past event, skill level, safety, format 避免只测“用户喜欢什么”。
Task type recommendation, writing, planning, QA, summarization, decision, troubleshooting 覆盖通用对话场景。
Difficulty easy, medium, hard, adversarial easy 测基本能力，hard/adversarial 测过度结合和冲突处理。
Conflict none, current-instruction-overrides, memory-hard-constraint, stale-memory 单独报告模型在当前指令、长期记忆和过时记忆之间的优先级处理。
Memory composition single-atom, mixed-label block, redundant overlap, partial overlap 体现 benchmark 对非原子记忆和重合记忆的诊断能力。
Domain daily, work, education, travel, shopping, entertainment, coding, health 领域是辅助维度，不应成为标签定义来源。

建议指标叙事：整体分数之外，应报告 atom-level precision/recall、A 类误用率、C 类遗漏率、mixed block 中的选择性使用准确率，以及 overlap/conflict 子集上的诊断结果。

9. 排除规则

主评测集应优先保证形式清晰。以下样本不适合进入 main set，但可进入诊断或边界分析。

  • atomic memory 无法唯一拆分，或一个 atom 内仍包含多个相互独立的命题。
  • ABC 标签依赖主观价值判断，而不是反事实回答变化。
  • query 直接泄露目标 atomic memory，使记忆使用不可评估。
  • memory block 的指代不明，例如“我不喜欢那个”但缺少对象。
  • 多个 atomic memories 组合后才产生标签，且无法归因到单个 atom。
  • 涉及敏感属性推断，但当前 query 未明确授权或不需要该信息。

10. 待讨论问题

这些问题会影响论文方法和 benchmark 的最终版本。

  • 主评测集是否只保留单 atom 可归因样本，组合依赖是否全部放入 diagnostic set？
  • A 类是否拆成 harmless irrelevant 与 harmful overuse trap？后者更能体现模型过度结合问题。
  • B 类是否需要细分为 style、ranking、explanation depth、example choice 等辅助类型？
  • conflict overlap 是否需要时间戳或 freshness 标签，用于区分过时记忆与长期稳定记忆？
  • gold test 是否全部人工双标，其他 split 是否允许 LLM 预筛后人工抽检？
