# CRK-2 构建协议 v2：100 条修复试验

本文档记录专家校准审查之后的数据构建协议修订。该协议作为独立版本运行，不修改 MemCalib v0.1 的既有数据与复现链路。

## 1. 标注对象

每个模型可见的记忆条目保留为完整的 `parent memory`。标注阶段将其拆为若干可独立判断的原子命题。原子边界以语义命题为准：主语、谓词以及保持命题成立范围所必需的对象、时间和条件共同构成一个原子。句法上的多个分句不自动触发拆分；只有当两部分能够独立取真值且分别改变回答时才拆分。

## 2. 影响强度与使用方向

每个原子记忆同时标注影响强度 `u*` 和使用方向 `a*`。

- `u* = A`：移除记忆后，回答中的结论、建议、约束、排序、语气和解释均不应出现可观察变化。
- `u* = B`：记忆引起局部适配、补充说明、警示或优先级变化，但回答主干在没有该记忆时仍然成立。
- `u* = C`：记忆控制核心结论、可行方案、安全边界或强制约束；忽略记忆会使回答对当前用户产生实质性错误。

使用方向 `a*` 取 `ignore`、`apply` 或 `correct`。A 仅允许 `ignore`；B/C 可以 `apply` 或 `correct`。如果回答应当明确纠正、拒绝或限定某条错误、危险或过期记忆，则该行为已经构成可观察的记忆使用，标签必须根据影响大小取 B 或 C，不能记为 A。

## 3. 反事实可观察性

每个原子记忆都记录 `without_memory_behavior`、`with_memory_behavior`、`observable_delta` 和 `minimal_evidence`。A 的 `observable_delta` 固定为 `none`，且证据列表为空。B/C 必须给出可在候选回答中直接识别的最小变化，模型内部推理变化或笼统的“与用户相关”不能作为证据。

## 4. 三项硬质检

1. **问题—记忆隔离**：最终问题不得陈述、改写、蕴含或预设任何计分原子。确定性后处理执行词法高召回检查，独立语义 QC 进一步判断语义重合与蕴含。
2. **原子独立性**：构建结果必须枚举全部无序原子对。任一原子对存在重合、蕴含或同义改写时，样本不得进入严格准入集。
3. **反事实可观察性**：B/C 缺少可观察差异，或 A 声称存在可观察差异时，确定性后处理直接拒绝。

此外，真实记忆仅可来源于原始问题或对话上下文。参考回答不得转化为用户记忆。每个样本只补充一个合成 hard A；该 hard A 不得使用需要主动纠正的危险偏好、错误诊断或错误事实。

## 5. 多阶段准入

流程由四个版本化步骤组成：

1. `29_prepare_crk2_v2_generation.py`：从既有严格准入源池中按数据源、主题和复杂度分层选择 100 条输入，并锁定哈希。
2. `30_post_crk2_v2_generation.py`：解析构建结果，执行 schema、证据、语言、标签—动作、问题泄露、反事实和原子对矩阵校验。
3. `31_prepare_crk2_v2_independent_qc.py`：为通过确定性检查的样本生成独立语义复核请求。
4. `32_post_crk2_v2_independent_qc.py`：根据逐原子和逐原子对结果重新计算 `strict_pass/review/reject`。复核模型自报的总体结论不直接决定最终状态。

## 6. 100 条试验输入

当前输入已经离线生成，尚未调用构建 API。数据源分布为 MedDialog 50 条、ChatDoctor 50 条；复杂度分布为 simple 32 条、medium 34 条、complex 34 条；12 个医学主题均被覆盖。API 运行完成后，应先检查确定性拒绝分布，再运行独立语义 QC，最后生成逐页人工审查界面。
