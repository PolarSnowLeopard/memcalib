4. 归一化、去重与分层抽样

4.1 统一源记录

不同数据集先被映射成同一种源记录：来源、split、稳定 ID、上下文、问题、回答、主题、许可、作者与链接。任何后续变换都保留这条谱系。

  • 结构字段完整且可解析
  • 问题与回答非空、长度合适
  • 主要语言符合英语构建目标
  • 过滤模板噪声、乱码和低信息单元
  • 精确文本去重
  • 近重复聚类后只保留代表项

4.2 为什么不能简单随机抽样

简单随机抽样会让大来源和高频主题占据多数样本，并掩盖医学安全、偏好触发、编程约束等稀有但关键能力。我们先固定领域总量，再按来源、主题和难度分层。

qh*  =  nd  ×  NhΣj∈d Nj

其中 h 是领域 d 内的来源×主题×难度单元；整数配额采用最大余数法闭合。

for each domain d:
    fix domain target n[d]
    count eligible records in every stratum h
    compute proportional raw quota q*[h]
    floor all quotas
    assign remaining seats by descending fractional remainder
    if a stratum lacks capacity:
        reallocate only inside the same domain
    rank candidates by quality score, then stable seeded hash
抽样的可复现性 相同的源快照、配置和 seed 会得到相同的记录顺序。稳定哈希只用于同质量候选之间的确定性排序，不会改变领域配额。

8. 按五类规范构造 Hard A

Hard A 的目的不是制造随机无关噪声，而是构造“看起来值得用、实际上不应留下任何回答痕迹”的近邻记忆。五类机制对应不同的过度使用诱因。

家族表面诱因为什么必须忽略数量
Factual judgment pollution用户背景、信念或地区经验似乎能解释当前问题客观判断必须依据当前证据，背景不能改变结论或证据权重3,000
Scope overreach记忆在相邻任务、环境或时间段中是真实的适用范围没有覆盖当前问题，不能跨范围推广3,000
Current evidence conflict旧记忆与当前事实竞争当前问题已提供更强或更新证据，旧记忆无决策权3,000
Profile/style near-neighbor用户画像或表达风格与答案形式邻近没有触发条件，不能改变实质建议或结论3,000
Untriggered preference用户确实拥有该偏好当前任务没有涉及该偏好的作用域3,000
∀ family f:  Nf = 3,000,  Nf,health = 1,500,  Nf,general = Nf,coding = 750
Hard A 的硬边界 错误、过时或不安全，而且回答必须显式纠正的记忆，不是 Hard A。它应当标为 B/C + correct。Hard A 必须允许“完全不提及”成为正确行为。

9. A/B/C 使用强度与动作方向

A · Suppress

零影响。只能配 `ignore`。任何改变结论、排序、证据权重、建议或原子特定措辞的行为都算 over-use。

B · Bound

有限支持。可以 `apply`，也可在相关内容错误时 `correct`，但不能不受约束地控制答案。

C · Control

必须实质性约束答案。可以 `apply` 或 `correct`。缺失或弱化会形成 under-use。

组合数量评测含义
A + ignore16,668不应观察到该原子对答案的专属影响
B + apply18,899有限使用，不能越界控制
B + correct133相关但仅需有限纠正
C + apply17,422答案必须被该约束显著控制
C + correct194必须显式纠正并据此改变答案

这种“强度 × 方向”分解避免把 A 错误地等价为“错误记忆”。A 只回答“当前问题是否应使用”，`correct` 才回答“相关内容是否需要纠正”。

11. 独立语义 QC 与迭代修复

独立 Judge 不读取构造模型给出的“通过”决定，而是重新判断复合块、原子标签、动作、rubric 和 Hard A 边界。结构错误只重试输出格式；语义失败不能靠重试改写成 strict。

阶段StrictReviewRejectInvalid处理
第一次全量独立 QC14,140296564015 个结构 invalid 定向重试后归零
Hard-A 定向语义修复后14,5523031450只覆盖 461 个新指纹
第二模型家族复核后14,90722710复核 423 个争议项，invalid 保留旧状态

11.1 修复循环

accepted = frozen strict records
residual = review ∪ reject ∪ invalid

while residual is not empty and a bounded repair exists:
    classify failure mechanism
    prepare requests only for repairable IDs
    run repair without touching accepted IDs
    validate new request and record fingerprints
    run fresh independent QC on changed fingerprints only
    overlay valid fresh decisions
    preserve old outputs, failures, and audit lineage

never convert reject/review to strict by threshold relaxation

第一次全量 QC 的 860 个非 strict 记录中，461 个具有可定向修复的 Hard-A 语义问题；423 个含复合块、真实原子或多原因争议，被推迟到第二模型家族复核。集合允许重叠，因为同一记录可有多个问题。

为什么需要第二模型家族 同一 Judge 既发现问题又验证修复会放大自洽偏差。对 423 个争议项使用不同模型家族，可暴露 family boundary、label/action 和 composite coherence 的判定差异。

14. 审计、复现与中间结果

每个模型阶段保存请求、原始输出、失败、结构 invalid、重试、指纹和后处理决策。修复采用 overlay 而不是原地覆盖：基础记录、修复记录、旧 QC 和新 QC 都能按 ID 和 fingerprint 追溯。

SOURCE

来源审计

原始 ID、split、许可、作者、链接、归一化和去重决策。

REQUEST

请求审计

request ID、输入 fingerprint、模型配置和提示词版本。

RESULT

响应审计

原始输出、finish reason、失败类型、重试和最终 resolved 结果。

QC

质检审计

validator、Judge 原始结论、规范化 reason 和状态变化。

REPAIR

修复审计

旧/新 fingerprint、允许的动作、证据变化和复核结果。

RELEASE

发布审计

manifest、统计、SHA-256、审查 HTML 和交付包清单。

可复现边界 确定性阶段可由相同源快照、配置和实现精确复算。依赖可变模型别名的生成和 QC 可能随服务端更新发生变化，因此论文实验必须引用锁定数据哈希、样本 manifest、提示词版本、模型别名和运行日期。

API Key 不写入任何请求、响应、日志、manifest 或交付包。大体积原始 API 中间结果只保存在本地审计目录；协作者 ZIP 包只包含最终数据、manifest、统计、审阅页面和方法文档。

15. 局限与论文表述建议

  • 不是自然流量样本：领域、来源和主题是能力覆盖配额，不能用于推断真实用户分布。
  • 模型辅助标注：即使经过双 Judge 和确定性修复，也不等价于大规模盲法专家标注。
  • 合成 Hard A 先验：每条都含一个 Hard A，适合测 OPB，但会形成已知的构造分布。
  • 两块接口限制：固定两个可见块便于控制变量，但不覆盖所有生产检索布局。
  • 纠正样本较少：只有 327 个 `correct` 原子，纠正能力的置信区间会更宽。
  • 公开权利未清完：Health 子集的许可与隐私风险要求公开发布前另做审查。
论文中可以准确声称 v2.1 的 15,000 条记录全部包含一个模型可见多原子真实记忆块和一个五类均衡 Hard A 块；最终发布集全部通过确定性验证，并经独立模型 QC、定向修复与尾部跨家族复核形成 strict-only 发布。
论文中不应声称 不应把数据称为自然分布、医学事实金标准、完全人工标注或已获准公开再分发；也不应把 v2.0 的七模型指标直接当作 v2.1 指标。
