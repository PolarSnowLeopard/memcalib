2. 一张图读懂完整构建路径

整个流程由八个不可跳过的门组成。每个门只接收上一步的合格对象；任何修复只作用于失败 ID，已通过项冻结。

01 · SOURCE公开源归一化

统一问题、回答、上下文、来源、许可证和署名字段；保留原始来源 ID。

02 · SAMPLE分层候选抽样

按领域、来源、主题和构造复杂度分层；先去重，再按稳定随机序确定配额。

03 · ADMISSION源语义准入

判断问答一致性、可回答性、信息量和证据支撑；仅 strict 进入构造池。

04 · BUILD18,000 条过量构造

生成原子记忆、A/B/C、动作、证据、反事实契约和可观察评分准则。

05 · REPAIR确定性校验与定向修复

修复结构、证据逐字落地和语义边界；形成 15,583 条确定性通过池。

06 · EXPAND长尾块内原子扩展

保留原有原子，增加 A+ignore 辅助原子，形成三档难度且每块最多 20 原子。

07 · QC改写与独立质检

多原子块改写成自然段；另一模型逐原子、逐块、逐记录复核。

08 · RELEASE精确配额发布

只合并 strict 与允许的 review，恢复原顺序，验证哈希、唯一性与完整署名。

核心隔离原则：构造模型、表面改写模型和独立 QC 承担不同职责；确定性 validator 不依赖模型自评；发布门依据重算后的记录级决策，而不是相信任一阶段自报的通过状态。

4. 抽样先控制覆盖，再由语义准入决定能否用于构造

4.1 分层配额不是按原始数据量直接抽取

候选选择按“领域 × 数据源 × 主题 × 构造复杂度”形成分层单元。大数据源不能仅凭体量占据全部配额；每个单元先获得按容量计算的初始配额，再用最大余数法离散化，只有单元自身容量不足时才在同一领域内重新分配。

分层初始配额
q(h) = n(d) × N(h) / Σj∈dN(j)
h 为分层单元，d 为领域，N 为可用容量。
确定性排序
rank(x) = quality(x), stable_hash(seed, id(x))
质量优先；同分时由固定种子与来源 ID 决定，便于复现。

该分布服务于能力覆盖和难度控制，不声称拟合真实线上流量。

6.4 原子扩展的构造条件

新增辅助原子必须能作为同一用户历史中合理出现的独立事实，但与当前问题的求解关系为 absent，不能在正确回答中留下内容、呈现、实现或安全足迹，也不需要被纠正。同一块内原子可以属于同一场景，但每个原子仍须可独立判真/判假，不能把一句复合事实伪装成多个原子。

扩展前共有 118,819 个隐藏原子；新增 115,402 个 A+ignore 后达到 234,221。新增量只增加负载，不改变原有 B/C 和答案约束。

7. 自然段改写隐藏原子边界，但不允许改变原子集合

v2.2 采用编号或显式分隔，虽然便于审计，却让模型直接看到原子边界。v2.3 在原子扩展完成后增加独立表面改写：多原子块被重写成一个连贯、自然、符合用户历史风格的段落；隐藏原子列表与块到原子的映射仍保留用于评分。

必须保持必须消除不允许新增
每个原子的全部命题、关键实体、数字、否定和条件数字编号、项目符号、Atom/Memory 等显式元标签隐藏原子之外的新事实、因果、偏好或结论
原子间可恢复的一一覆盖关系机械拼接和逐句模板重复对当前问题的提示、答案线索或纠正

确定性门先检查 ID、原子映射、关键 token、显式编号和模式完整性；语义门再判断段落是否确实覆盖全部原子且没有增加命题。两种检查互补：前者擅长捕获可机械验证的不变量，后者覆盖同义改写和隐含语义。

8. 独立 QC 同时检查新增原子、自然段和整条记录

QC 不是只给记录一个总分，而是先生成逐原子、逐块和全局检查，再由最严重的失败决定记录级状态。

8.1 逐新增原子检查

  • Atomicity：是否可独立判真/判假。
  • Same-user plausibility：是否像同一用户可能拥有的历史。
  • Query relation：与当前问题必须为 absent。
  • Answer footprint：content、presentation、implementation、safety 均为 none。
  • Correction：不能要求答案显式纠正。
  • Distinctness：不能复制原有原子或同块新增原子。

8.2 逐块检查

  • Coverage：段落覆盖块内每一个隐藏原子。
  • No extra proposition：段落没有隐藏列表外的新命题。
  • Critical values：数字、单位、否定和条件未丢失。
  • Naturalness：是连贯自然段，不是伪装列表。
  • Coherence：同块原子能形成合理记忆场景。
  • No contamination：没有把当前问题或目标答案写回记忆。

8.3 记录级合并规则

严重度顺序
strict_pass < review < reject < invalid
记录决策
decision(i) = max severity(all atom, block, global checks)

strict_pass 表示所有硬门通过且无边界疑点；review 仅用于不影响答案、标签或可评分性的边界判断；reject 表示存在真实质量失败；invalid 表示 QC 输出结构不完整或无法解析。reject/invalid 不得进入发布。

模型训练或评估时的输入投影

完整 JSONL 同时包含模型可见输入与隐藏监督。给回答模型的输入只能投影为：

model_input(i) = { current_questioni, ordered(memory_texti,1…K) }

不得向被评模型暴露隐藏原子、A/B/C、动作、反事实契约、usage rubric、pairwise audit 或 QC decision。隐藏字段只用于评分、辅助训练或方法审计，并应对 benchmark holdout 做显式防泄漏。

12. 限制、稳健性与论文表述边界

  • 受控分布而非流量估计：领域、来源、块数和难度均为实验设计分布，不能解释为真实用户请求频率。
  • 模型辅助标注：新增原子、自然段和语义 QC 使用模型辅助，但以确定性不变量、独立 QC、定向修复和人工尾部审计约束。
  • review 的含义：1,077 条 review 是无硬失败的边界案例。主要实验应报告是否纳入这些记录，并做 strict-only 敏感性分析。
  • A 数量的解释：新增 115,402 个 A+ignore 是为构造高负载干扰上下文，不能据此声称自然记忆系统中 A 的真实先验为 84.35%。
  • 来源事实边界：来源回答用于构造锚定，不是医学或通用事实的最终权威；模型使用数据进行训练后仍需独立安全评估。
  • 许可证与署名：Stack Exchange 项已完成署名，但其他来源尤其健康数据仍需在公开再分发前做额外权利与隐私审查。
  • 可比性：与 v2.1/v2.2 比较时应保持问题集合、输入投影、解码设置和 judge 协议一致，并分别报告三档难度结果。
