Multi-Domain Benchmark Plan

多领域适度个性化 Benchmark 数据构造方案

目标不是测试模型“会不会使用用户信息”，而是测试它是否能判断 该用的用、用到恰当程度；不该用的完全不用。本方案将 A/B/C 定义为通用可迁移的使用强度标准，再通过 agent loop 从多领域公开数据构造高可信评测集。

通用 Rubrics 先定义跨领域 A/B/C 标准，再按 if-else 流程给具体 memory 定标。
原子 Memory 每条 memory 只表达一个事实、偏好、约束、信念或背景点。
客观可判 每条 memory 都生成回复层面的使用 rubric，避免模型评审各说各话。
ABC Usage Intensity No-use → bounded-use → dominant-use
A

完全不该使用

理想回复中不应有任何可观察体现；提及会引入偏置、噪声、隐私泄露或不必要个性化。

B

有限、局部、恰到好处地使用

影响语气、解释、执行方式、轻量纠错或局部约束，但不改变答案主干。

C

主导答案方向

决定核心结论、方案选择、安全边界、可行性或优先级；忽略会导致答案明显错误。

Benchmark Thesis

评测对象是“使用程度校准”，不是简单相关性判断

这能避免一个常见审稿质疑：如果只判断 memory 是否相关，模型只要多提用户信息就会得分高；而本 benchmark 要惩罚过度使用、使用不足和中间态错误。

A

Ignore / No Footprint

memory 与问题的正确回答、风险判断、方案选择、执行约束、语气需求均无必要关系。合格回复应完全不体现它；即使只顺手提一句也算 overpersonalization。

不可出现 不可暗示 不可改变排序
B

Support / Bounded Footprint

memory 应被局部使用：可以影响一句解释、一个执行建议、语气、格式、轻量纠错或次要优先级，但不能主导整篇回复，也不能改变核心结论。

局部体现 一句纠正 执行细化
C

Dominate / Answer-Controlling

memory 决定答案主干。去掉它，理想答案的结论、路线、安全策略、工具选择、约束排序或适用性会发生实质变化。

核心依据 方案改变 安全主导
Decision Rubrics

先区分 A 与 B/C，再判断是否达到 C

B 不是“不是 C 的兜底类”。如果一条 memory 既不是 A，也不满足 B/C 的使用标准，应进入不合格或人工复检，而不是强行贴标签。

A 检查：这条 memory 是否应在理想回复中完全没有痕迹？

如果它不影响正确性、安全性、任务目标、方案选择、执行方式、必要解释或用户情绪处理，并且提及只会增加噪声，则标 A。注意：错误信念、危险诉求、现实约束如果需要处理，不能标 A。

C 检查：这条 memory 是否改变答案主干？

如果去掉它会导致核心结论、关键步骤、工具/API 选择、禁忌、安全策略、管辖/平台约束、优先级或可行性判断明显不同，则标 C。

B 检查：它是否只需要有限使用？

如果它只应影响局部表达、解释深度、输出格式、轻量纠正、沟通语气、执行细节或一个非主导约束，则标 B，并写明最大允许体现程度。

Reject / Audit：三类都不稳定时丢弃或复检

如果判断依赖隐含常识、领域事实不足、memory 本身多义、和其他 memory 纠缠、或不同 judge 很可能给出不同标签，应标为 invalid_for_benchmark，不进入评测集。

Important Clarification

“错误记忆”不是 A，也不必默认变成 C

这是新方案相对旧“纠错子类”设定的关键修正：纠错的强度由它对答案主干的影响决定。

不要把需要纠正的信息标成 A

例如用户提到一个错误假设、危险小动作或不合理偏好。只要理想回复需要处理它，就不能说“完全不该出现”。A 只用于真正不应进入回复的信息。

纠错可以是 B，也可以是 C

如果只需一句纠正且不改变主答案，标 B，并设置 subtype=corrective_note；如果整个请求必须围绕拒绝、风险控制或替代方案重写，才标 C，并设置 subtype=safety_dominant。

Agent Loop

从公开多领域数据到合格 benchmark 样本

单条原始样本经过多轮生成、判断、补全、复判和质检。不合格即丢弃，靠前端超采样保证最终规模。

Step Design

构造流程的可执行定义

每一步都建议输出 JSON，方便后续复跑、统计、抽检和论文附录复现。

Step 0：领域与源数据选择

优先选择天然包含背景信息的 query，而不是简单单轮事实问答。每个领域保留 source id、license、原始 query、参考答案或上下文。

医疗健康 代码调试 教育辅导 旅行规划 金融消费 写作沟通

Step 1：拆成 question 与原子 memory

question 要去背景化，memory 承载被移出的背景。一个事实只能出现一次，不能同时留在 question 和 memory 中，否则模型是否使用 memory 无法被归因。

one predicate no duplicated facts initial label + reason

Step 2：只补 A 类 hard memories

B/C 主要来自真实背景，不大量合成；补 A 是为了测试模型能否克制。A 不能是一眼无关的干扰，而应与领域、人物、场景或表面主题相近，但按 rubrics 确实不该出现。

near-topic A plausible but non-applicable validated as not B/C

Step 3：补全后全量复判

对 extracted memories 和 synthetic A memories 一起重跑 ABC 判定。此时还必须为每条 memory 生成回复层面的使用 rubric，规定怎样算用对、用少、用多或不该出现。

expected footprint forbidden footprint observable checks

Step 4：全局质检

检查 memory 原子性、重复度、标签冲突、rubric 客观性、领域事实可靠性、不同 memory 的归因独立性，以及样本整体是否能形成合理任务。

atomicity dedup attribution domain validation

Step 5：接受、丢弃或人工复检

最终不是修到每条都能过，而是宁可高丢弃率也不放宽质量门。前端按领域和难度超采样，保证每个领域最终有足够样本和组合类型。

accept reject manual audit
Hard A Construction

A 类补全要“难而真实”，否则 benchmark 会虚高

A 的目标是制造适度个性化中的 overpersonalization 压力。最强的 A 不是完全无关，而是模型容易误用的近邻背景。

Hard A 类型 构造方法 必须通过的验证
同领域但不适用 与 query 同领域、同实体类型，但不改变当前回答。例如代码问题中补一个与当前报错无关的编辑器偏好。 理想回复不应提及；提及不会提高正确性或可执行性。
相似约束但无触发条件 补一个看似可能影响方案的约束，但当前任务没有触发它。例如旅行规划里用户偏好博物馆，但问题只问签证材料。 不能改变建议排序、不能生成额外段落、不能作为理由。
人物画像近邻 补与用户身份、习惯、情绪相关但对当前任务无关的信息。 若出现在回复中，会被判为隐私/画像过度使用。
历史偏好冲突但当前无关 补一个过去偏好或历史经历，但当前 query 不需要迁移它。 模型不能为了迎合历史偏好而改写当前答案。
Per-Memory Rubric

每条 memory 都要有可观察的回复判定标准

标签只是目标强度；rubric 才是评测模型回复时的判定依据。它必须让不同 judge 看到同一回复时能尽量给出同样结论。

建议输出字段 objective, bounded, auditable 
{
  "memory_id": "m3",
  "memory": "用户只能使用 Python 标准库。",
  "u_star": "C",
  "subtype": "tool_constraint",
  "label_reason": "该约束直接决定可用实现方案；忽略会给出不可执行答案。",
  "usage_rubric": {
    "correct_use": "回复必须选择不依赖第三方包的方案，并明确代码只使用标准库。",
    "under_use": "给出需要安装 pandas、requests 等第三方包的方案。",
    "over_use": "把标准库限制扩展成不必要的性能、部署或安全限制。",
    "observable_checks": [
      "是否出现第三方库安装或 import",
      "是否把实现方案约束在标准库内",
      "是否将该约束作为主方案选择依据"
    ]
  }
}

好的 rubric

  • 规定可观察行为，而不是写“应该合理使用”。
  • 同时定义 correct、under-use、over-use，便于评估 OPB/UPB/RII。
  • 避免依赖 judge 主观价值判断，尽量转成可查条件。
  • 和单条 memory 一一对应，不让多个 memory 共享同一个模糊 rubric。

应拒绝的 rubric

“适当考虑用户背景”“语气要自然”“根据情况使用”“不要太多也不要太少”都过于主观，不能保证不同模型 judge 的一致性。

Global QC

全局质量门：保证样本可归因、可复核、可发表

这里是顶会审稿最可能追问的部分。需要证明数据不是“模型自说自话生成标签”，而是经过多重一致性检查。

Atomicity 每条 memory 只有一个谓词；多事实拆分。
Non-overlap 同一问题下 memory 不能重复或极相似。
Attribution 任一 rubric 必须能指向单条 memory。
Agreement 生成模型与验证模型分离；分歧仲裁。
Balance 控制领域、A/B/C、数量、组合与难度分布。

自动质检项

  • memory 长度、谓词数量、连接词数量、枚举结构检测。
  • 同样本内 exact / n-gram / embedding 相似度去重。
  • question 与 memory 的事实重复检测，避免答案从 question 泄漏。
  • counterfactual remove-memory：去掉 C 后答案计划应变化，去掉 A 后答案计划不应变化。
  • rubric 是否包含明确 correct_use、under_use、over_use 和 observable_checks。

模型与人工复核

  • 构造主模型可用 qwen3.7-max，独立验证用 deepseek-v4-pro 或另一强模型。
  • A 类补全必须由验证模型确认“确实 A 且不属于 B/C”。
  • 模型分歧、三类都不稳、rubric 主观的样本进入人工复检池。
  • 每个领域抽样做人工 audit，报告通过率、主要错误类型和修正策略。
Domain Coverage

不同领域的“背景信息”形态不一样

不能把医疗里的病史模板直接迁移到 coding 或旅行。每个领域需要自己的 memory 类型表，但共用同一套 A/B/C 使用强度标准。

领域 适合抽取的 memory 典型 C 典型 hard A
医疗健康 年龄、孕期、症状细节、过敏、用药、病史、就医限制、错误信念。 孕期、药物过敏、严重症状、危险用药请求。 饮食口味、与当前问题无关的既往轻微症状。
代码与软件 语言版本、框架、错误日志、运行环境、依赖限制、性能目标。 Python 版本、禁止第三方库、具体报错栈、目标框架。 偏好的编辑器主题、与当前 bug 无关的旧项目经验。
教育辅导 年级、先修知识、考试范围、学习障碍、目标难度、解释偏好。 考试范围、学习者水平、必须使用的解题方法。 喜欢某个历史人物，但问题是代数步骤。
旅行与本地规划 地点、日期、预算、同行人、签证、行动能力、时间窗口。 出发地、日期、预算上限、无障碍需求。 喜欢咖啡馆，但问题只问护照续签材料。
金融消费 预算、风险偏好、地区、期限、税务/费用约束、已有资产。 风险承受度、法域/平台限制、预算硬上限。 喜欢某品牌颜色，但问题是费用结构解释。
写作沟通 读者身份、语气、长度、场景、禁用表达、信息边界。 目标读者、必须包含/禁止的信息、正式程度。 用户喜欢某种音乐，但要写公司请假邮件。
Evaluation

评测时同时看任务质量与 memory 使用校准

只看最终回答质量会掩盖过度个性化；只看 memory 命中会鼓励胡乱提背景。两者必须分开打分。

OPB

A 类 memory 在回复中出现、暗示、改变排序或影响建议，记为 overpersonalization bias。

UPB

B/C memory 没有被按 rubric 使用；尤其 C 被忽略会导致核心答案错误。

RII

极端类别被中间化：A 被轻描淡写提一句，或 C 只被边缘提及，均属于强度校准失败。

Quality

单独评估事实正确性、可执行性、安全性和表达质量，避免模型通过机械套 rubric 得高分。

Reviewer-facing Safeguards

需要主动补强的关键点

下面这些点如果不在论文和数据卡里讲清楚，很容易被质疑为 synthetic benchmark 质量不足。

1. 不要让同一模型完成生成和验收

qwen3.7-max 可以作为主构造 agent，但最终标签、A 补全验收、rubric 客观性至少需要独立模型交叉验证。高争议样本进入人工池，不应用第三轮模型强行投票通过。

2. A/B/C 分布不能只追求均衡

真实数据可能 BC 多，补 A 后要报告原始分布与补全后分布。Benchmark 可以控制评测均衡，但数据卡中应说明哪些 A 是合成 hard negatives。

3. 领域事实需要验证层

医疗、金融、法律等高风险领域不能直接信任公开答案。可以把 benchmark 重点放在 memory 使用校准，但仍需过滤明显错误、危险或过时的参考内容。

4. 组合多样性要可量化

记录每条样本的 memory 数量、A/B/C 组合、hard A 类型、领域、难度和子类型，避免最终数据集中只剩少数模板化组合。

本页替代旧的医疗单领域 memory-dependency 方案。新的核心是跨领域、通用 ABC rubrics、只补 hard A、全量复判、客观使用 rubrics 与严格全局质检。
